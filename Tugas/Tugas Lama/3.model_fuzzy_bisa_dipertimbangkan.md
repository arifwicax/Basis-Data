**Fuzzy sangat cocok** untuk kasus ini, terutama karena banyak parameter operasional tidak selalu memiliki batas tegas.

Contohnya, istilah seperti:

* Fuel Ratio **rendah, sedang, tinggi**
* produktivitas **buruk, cukup, baik**
* payload **rendah atau optimal**
* idle time **normal atau berlebihan**
* populasi alat **kurang, sesuai, berlebih**

tidak selalu tepat jika hanya ditentukan dengan aturan batas kaku.

## Mengapa fuzzy cocok?

Misalnya digunakan aturan biasa:

```text
Jika idle time > 20%, maka idle berlebih.
```

Masalahnya, idle time 19,9% dianggap normal, sedangkan 20,1% dianggap berlebih. Padahal perbedaannya sangat kecil.

Dengan fuzzy:

* idle time 19,9% dapat memiliki keanggotaan:

  * normal = 0,52
  * tinggi = 0,48
* idle time 20,1%:

  * normal = 0,48
  * tinggi = 0,52

Hasilnya lebih halus dan lebih sesuai dengan kondisi operasional nyata.

# Mamdani atau Sugeno?

## Fuzzy Mamdani

Cocok apabila keluaran ingin mudah dipahami manusia.

Contoh keluaran:

* efisien;
* cukup efisien;
* tidak efisien.

Kelebihan:

* mudah dijelaskan;
* aturan mudah dibaca;
* cocok untuk dashboard operasional;
* sesuai dengan pengetahuan pakar.

Kekurangan:

* proses defuzzifikasi lebih berat;
* kurang cocok untuk keluaran numerik yang sangat presisi.

## Fuzzy Sugeno

Cocok jika keluaran ingin berupa nilai numerik.

Contoh keluaran:

* skor efisiensi 72,5;
* estimasi Fuel Ratio 0,89;
* rekomendasi jumlah unit 8;
* tingkat risiko pemborosan 76%.

Kelebihan:

* komputasi lebih ringan;
* mudah diintegrasikan dengan optimisasi;
* cocok untuk prediksi angka;
* lebih mudah dikombinasikan dengan machine learning.

Untuk hackathon ini:

> **Mamdani cocok untuk klasifikasi kondisi dan rekomendasi operasional**, sedangkan **Sugeno cocok untuk menghasilkan skor efisiensi atau estimasi Fuel Ratio**.

# Contoh rancangan sederhana

## Input

### Fuel Ratio aktual terhadap target

[
\text{Deviasi Fuel Ratio}
=========================

\frac{\text{Aktual}-\text{Target}}{\text{Target}}\times 100%
]

Himpunan fuzzy:

* rendah: −10% sampai 5%
* sedang: 0% sampai 15%
* tinggi: 10% sampai 30% atau lebih

### Produktivitas terhadap target

[
\text{Achievement}
==================

\frac{\text{Produktivitas Aktual}}
{\text{Produktivitas Target}}
\times 100%
]

Himpunan fuzzy:

* rendah: 0–80%
* sedang: 70–100%
* tinggi: 90–120%

### Idle ratio

[
\text{Idle Ratio}
=================

\frac{\text{Idle Hours}}
{\text{Engine Hours}}
\times 100%
]

Himpunan fuzzy:

* rendah: 0–10%
* sedang: 5–25%
* tinggi: 20–50%

## Output

Skor efisiensi 0–100:

* 0–20: sangat tidak efisien
* 20–40: tidak efisien
* 40–60: cukup efisien
* 60–80: efisien
* 80–100: sangat efisien

# Apakah fuzzy lebih baik daripada machine learning?

Tidak selalu. Keduanya memiliki fungsi berbeda.

| Fuzzy                                   | Machine Learning                           |
| --------------------------------------- | ------------------------------------------ |
| Cocok ketika pengetahuan pakar tersedia | Cocok ketika data historis tersedia banyak |
| Mudah dijelaskan                        | Dapat menangkap pola kompleks              |
| Bisa digunakan walau data terbatas      | Membutuhkan data yang cukup                |
| Aturan dapat disesuaikan dengan SPO     | Pola dipelajari dari data                  |
| Bagus untuk keputusan linguistik        | Bagus untuk prediksi numerik               |

Untuk hackathon dengan data terbatas dan standar operasional yang jelas, fuzzy justru bisa menjadi pilihan utama.

# Rekomendasi model

Model yang saya sarankan adalah:

> **Fuzzy Expert System untuk Penilaian Efisiensi Fuel Ratio dan Identifikasi Penyebab Pemborosan Berbasis Parameter Operasional.**

Strukturnya:

```text
Data Fuel
Data Produktivitas
Data Payload
Data Idle Time
Data Utilization
Data Populasi Alat
        ↓
Fuzzifikasi
        ↓
Rule Base berdasarkan SPO dan pakar
        ↓
Fuzzy Inference
        ↓
Defuzzifikasi
        ↓
Skor Efisiensi, Penyebab, dan Rekomendasi
```

Bahkan lebih kuat jika dibuat **hybrid**:

```text
Fuzzy
→ menilai tingkat efisiensi dan rekomendasi

Machine Learning
→ memprediksi konsumsi atau Fuel Ratio

Optimisasi
→ menentukan jumlah alat yang paling efisien
```

Jadi, **fuzzy sangat cocok**, khususnya untuk menerjemahkan parameter operasional yang bersifat tidak pasti menjadi skor efisiensi dan rekomendasi yang mudah dipahami. Untuk prototipe hackathon, saya akan memilih **Fuzzy Mamdani** karena lebih mudah dipresentasikan, divalidasi dengan pakar, dan dijelaskan kepada juri.
